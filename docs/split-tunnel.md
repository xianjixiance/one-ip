# 网站分流检测

访问 `/network/exits`，默认以网站列表显示实际检测域名、出口 IP、地区、运营商、检测状态和采样时间。也可以切换到出口分组或地图，按分类、站点、IP、运营商和结果状态筛选。

## 验证规则调整

1. 等待检测和归属查询完成，点击“保存为基准”。基准包含全部站点，不受当前筛选影响。
2. 在自己的代理客户端调整规则，再点击“全部重测”或某个站点的“重测”。
3. 使用“对比有变化”筛选查看出口变化、恢复读取和本次无法读取的站点。重测单站不会更新其他站点的采样时间。
4. “设置预期出口”支持指定 IP 或两位国家／地区代码，也可对一个分类批量设置。批量设置会覆盖所选站点原有的预期，不修改代理客户端配置。

基准和预期保存在本浏览器的 localStorage，不上传到服务器；存储被禁用时会提示仅在本页临时保留。查询历史不跨设备同步。隐藏 IP 开关同时覆盖当前结果、基准、预期、分组、地图弹窗及联合诊断中的地址显示。

## 如何解读结果

- 读取成功：本次请求读到了有效 IP，并不证明代理配置正确或业务服务已解锁。
- 暂不支持：已知没有接入可用检测方式，不发请求，也不计入可检测站点的分母。
- 检测超时：请求开始执行后超过 6 秒。
- 接口响应异常：浏览器能读取到非成功 HTTP 状态。
- 未返回有效 IP：读到的响应没有有效地址。
- 请求失败或跨域受限：浏览器无法读取响应，不能可靠区分所有跨域、重定向、扩展拦截与网络原因，也不代表网站一定无法访问。

站点详情始终展示实际检测 URL。例如 Discord 探测 `gateway.discord.gg`，其结果不能代表该服务所有域名。检测禁止跟随重定向，避免把另一个域名的出口当作原目标。请求在浏览器内发出，不经过 Worker 代理；最多同时执行 6 个站点检测，可停止排队中的请求。失败项可批量重测，不对每个失败请求自动重复探测。

比较 IPv6 时先规范化地址。没有本次结果、未取得地区或检测目标已改变时，不推断匹配成功。国家或地区匹配依赖外部 IP 数据源。

## 联合诊断

按需启动 HTTP、IPv4、IPv6、DNS 和 WebRTC 检查，整体最多采样约 20 秒，保留已经完成的 DNS 采样。WebRTC 与自身的 HTTP 对照端点比较；不同地址族分别核查。DNS 结果是解析器地址，不能直接和网站出口相等比较。结果不同不自动判定泄漏，未采集到结果也不代表安全。

基础功能继续使用 Cloudflare Workers + Static Assets；本次增强没有增加数据库、付费服务或账户系统。外部检测接口仍可能因网络环境或服务策略变化而不可用。
